# Daily Driver: developer notes

A personal, long-lived self-monitoring and self-development app. Plain ES modules, no build step, no dependencies. It is an installable web app (PWA); all data lives in the browser's localStorage on the user's device.

## Run and test
```sh
python3 -m http.server 8000            # serve the repo root
node tests/smoke.cjs <path-to-playwright> 8000   # end-to-end smoke test (needs Chromium)
node tests/ics.test.mjs                          # calendar reader unit tests
node tests/nlp.test.mjs                          # quick-add parser unit tests
sh tests/widgets/run.sh <path-to-playwright> 8000 # widget Java on the JVM against stand-in Android classes (needs java)
```
Run the smoke test after any change to `js/`, and the widget test after any change to `android-native/`, `js/ics.js` or the snapshot in `js/widgets.js`. It covers every screen, persistence and the v1 to v2 data migration.

## Layout
- `js/core.js`: shared state `S`, UI state `ui`, the `app` registry, `register()`, `render()`, `commit()`.
- `js/store.js`: schema, `migrate()`, save/export/import. **State shape is documented in `blank()`.**
- `js/logic.js`: domain logic (habit streaks, task ranking and completion). No HTML.
- `js/util.js`: pure helpers (dates, escaping). `js/ui.js`: shared HTML snippets (tabs, bars, heatmap).
- `js/data.js`: frameworks and thinking models. `js/casebook.js`: the consulting casebook shown under Learn > Cases (playbook, cases, practice problems, toolkit, HR tech map).
- `js/views/*`: screens in the bottom bar: Home, Tasks, Notes, Calendar, Learn (News and Cases) (five tabs; that is the limit). `js/agenda.js`: everything dated on a day (calendar events, hand-typed events, deadlines, to-dos, email facts, tasks due) with a kind; the Calendar tab and the widget snapshot both read it. `js/views/notes.js` and `js/notes.js`: the notes app (books, pages, blocks: text, heading, bullet, number, checklist; Enter continues a list, `- `, `[] `, `# `, `1. ` typing shortcuts, a format bar, pin, search, checklist to tasks). Pages are `S.pages`, books `S.books`; old flat `S.notes` are converted by `migrate()`. The editor never re-renders while typing (`data-bind`); structural changes set `ui.nb.focus` and `app.after` puts the caret back. `js/links.js`: finds links in an event's description or place, or a task's link field, and ranks them (meeting, document, form, mail); `linkBtns()` in `ui.js` draws them as small buttons (Join, Open, Form, Mail) on Home, Calendar and Tasks, and `Links.java` plus the `u`/`uk` snapshot fields do the same on the widgets. The email-to-calendar routine puts meeting links, document links and the Gmail message link on their own lines in an event's description. Tasks can have a due time (a reminder fires then), a repeat (daily, weekdays, weekly, monthly; ticking moves the date on) and a link. Notes deletes go to Trash (`trashed` time, purged after 30 days, restorable); quick jots never cut text. Tasks have steps (`subs`), a note, snooze (1 hour, tomorrow, next week), filters (All, Today, Upcoming, Priority, No date) and Undo on delete through `toast()` in `ui.js`. Events typed into the app (`S.events`) can be edited, deleted (with Undo) and repeat (daily, weekdays, weekly, monthly, with skipped dates) through `occursOn()` in `util.js`. `js/views/search.js`: one search over tasks, notes, habits, the calendar (30 days back, 90 ahead), news, saved stories and the casebook; the Search button sits next to the dots on every screen. Learn > News can save stories (`S.saved`), shown under Saved. The Android app writes an automatic backup once a day to its private storage (`autoBackup()` in `native.js`, last 7 kept, restorable in Settings). Home and Calendar redraw every minute when nothing is being typed. `js/files.js`: photos and files attached to note pages (`files` on a page), stored in the app's private storage on the phone (IndexedDB in a browser), not in the JSON backup. Task and habit notifications carry Done and Snooze buttons (`initNotificationActions()` in `native.js`, handled in `main.js`). Synced Google events get an Edit button that opens the event in Google Calendar (`gcalLink()` in `calendar.js`, built from the iCal UID and the calendar's email; repeating instances add their start time). The Tasks widget shows steps, links and a Priority filter, the News widget a Saved filter. `js/nlp.js`: natural-language quick add ("Submit DHRM fri 5pm !" sets date, time, priority, repeat; tests in `tests/nlp.test.mjs`), used by Home and Tasks with a live preview (`app.inputs.nlp`). `js/log.js`: the problem log (errors, failed actions and forms, screens that fail to draw), shown and shareable in Settings. Every save is mirrored to `state.json` in the app's private storage (`setMirror` in `store.js`); at start-up the newer of web storage and that file wins (`adopt()`), so the 5 MB web-storage limit or a cleared web view loses nothing. Daily notifications are laid out 14 days ahead. A link shared into the app goes to Learn > Saved (read later); other shared text becomes a task and a note. `js/views/academics.js` and `js/study.js`: Classes & exams (no tab; from Home's exam banner and the Calendar header): exams (`S.exams`, with revision topics, countdowns and a daily target) appear on the calendar as deadlines; attendance is marked on past classes (`S.attend`) on the Home timeline or there, per course with a minimum (`S.study.minAttend`). `js/views/review.js`: the weekly review (Sunday and Monday banner): the week's numbers, what to do with open tasks, and next week's top three (`S.reviews[monday].top`), shown on Home all week. `js/taskui.js`: the shared task row, edit sheet and menu. Widgets ignore yesterday's ticks when the snapshot is older than today (`Widgets.stale()`). `js/views/routine.js`: Routine, the habits page (no tab; opened from the Habits card on Home or from Settings). A habit is fixed days, a weekly goal (`goal`, e.g. gym 5 a week, with `options` such as Push/Pull/Legs recorded per session in `habitInfo`) or a counter (`target`); `habitLog` stays a plain done flag so streaks and widgets keep working, and `logic.js` has the weekly maths. Habits may carry a nudge `time`. `js/sections/settings.js`: Settings (opened from the three dots at the top right of every screen, built by `me()` in `js/ui.js`; no tab), which also manages habits. The old Track, Goals, Career, Money, Body and Focus screens were removed on purpose; their data stays in `blank()` and in backups, never dropped.
- `js/ics.js`: iCalendar reader (time zones, all-day, recurrence). `js/calendar.js`: calendar sync, secret addresses kept in their own storage keys (never in `S` or backups). The Android widgets re-read the calendars on their own: `IcsReader.java` is a Java twin of `ics.js` and `CalendarSync.java` mirrors `calendar.js` and `agenda.js` (kinds, hidden words, the Needs-you list). Keep the pairs in step; `tests/widgets` compares the two readers on `tests/fixtures/sample.ics`. `js/native.js`: Android bridge (uses `window.Capacitor.Plugins`; there is no bundler, so never call `registerPlugin` or import `@capacitor/*` in `js/`). The smoke test simulates the bridge. `js/reminders*.js`: local notifications.
- `js/main.js`: event delegation and boot. `sw.js`: service worker (network first). Bump its cache name when adding files to `ASSETS`.
- `js/schedule.js`: the day's items from all sources. `js/widgets.js`: builds a JSON snapshot after each change and hands it to `WidgetBridge.update` (`js/native.js`). `android-native/`: Java widget providers, layouts and manifest receivers that CI copies into the generated Android project. Widgets read the snapshot, never the web app. There are eleven: Overview, Schedule, Tasks, News, Calendar, Habits, Next up, Quick add, Problem of the day, Deadlines, Notes (pinned and recent pages; targets `notes:page:<id>`, `notes:new`, `notes:add`) (a removed widget's kind number, 4, stays unused). Every widget is a header (with a progress bar for Tasks and Habits, and a compact version when short), buttons and a scrolling `ListView` (Quick add is four tiles, Deadlines are countdown tiles, Next up is one big card) fed by `WidgetListService` and `WidgetRows`; row taps go through one mutable pending-intent template to `WidgetRouteActivity`, which has no screen and either opens a tab or applies a tick. The calendar widget has the app's four modes (Month, Week, Day, Agenda); month, week and day draw the grid or strip above a list for the picked day, the picked day is a bordered tile and today a filled circle, and a + button opens the app's add-event form; its state (`calState()`: mode, picked day, shown month or week) is validated on every tap and every draw, and each cell sets its highlight both ways so no launcher can keep a stale one. `tests/widgets` fuzzes it with 800 random taps. Any snapshot field change needs the Java side updated too. Widgets are interactive: ticks and page flips are handled natively and queued as ops that `syncFromWidgets()` applies when the app next opens; a tap carries a target like `learn:news` or `plan:tasks:add` that `openTarget()` turns into a tab (old `track:*` targets open Home; `plan:*` maps to Tasks, `plan:notes` to Notes). Layout adapts to the widget's height. `NewsSync.java` lets the News (and Everything) widget fetch `data/news.json` from GitHub by itself on each system refresh, so news stays fresh with the app closed; task due labels are computed natively from the due date for the same reason.
- `brief/`: rules and template for the daily brief routine (see Privacy).

## How things work
- Rendering is whole-screen template strings. Every interaction goes through `data-act` (click), `data-form` (submit) or `data-bind` (live typing, no re-render). Handlers are registered by each module and run through `commit()` which saves and re-renders.
- Always wrap user text in `esc()` before putting it in HTML.
- Extension points so modules do not import each other: `app.nudgeSources` (lines for "Needs attention"), `app.taskSources` (derived tasks for the Plan matrix), `app.todayCards` (extra cards on Today).

## Adding things
- **New screen:** create the file, call `register({ id, label, nav: <position>, enabled?, render, actions, forms, inputs })`, import it in `main.js`, add it to `sw.js` ASSETS. The bottom bar is built from views that have `nav` (keep it to five). A view without `nav` (Settings) is opened with a `data-nav` link. To make a module switchable, add a flag to `modules` in `store.js` and a row in Settings.
- **New tab inside a screen:** add it to that screen's tab list and page map (see `plan.js`, which pulls in the Career pages).
- **Changing stored data:** add the new field with a default in `blank()`. If an old shape must change, bump `SCHEMA` and add a step in `migrate()`. Never drop user data silently, and add a migration test to `tests/smoke.cjs`.

- Android entry points: text shared into the app (`ACTION_SEND`) becomes a task and a note through the same op queue as widget ticks (`capture`), and four long-press icon shortcuts are in `android-native/res/xml/shortcuts.xml`; the workflow patches both into the generated manifest.

## Privacy rules (the GitHub repo is public)
- The secret iCal addresses are also copied into the Android app's private storage (SharedPreferences) so widgets can refresh by themselves. They never go anywhere except Google's own calendar servers.
- Never commit real personal data: email content, deadlines, names, class schedules, addresses, tokens, calendar addresses.
- `data/brief.json` is sample data only. The live daily brief is published to a private Claude page by a scheduled routine that follows `brief/RULES.md` and fills `brief/page.template.html`.

## Product principles
- Daily use should take minutes. Capture is one field; there is no sorting step. The user opens the app for fun, so every screen must look finished and feel light; when in doubt, remove rather than add.
- Show progress honestly (streaks skip unscheduled days).
- Learn is news plus a consulting casebook for an HR transformation (HCOT) career. Keep new learning content there and keep it factual; cases summarise widely reported public accounts and say so.

## Visual design rules
- v3 look (`css/v3.css`, loaded after `styles.css` and overriding it): "Paper" in light (warm off-white page `#F5F2EC`, ink text, hairlines) and "Night" in dark (near-black `#0E1013`). Calm and list-first: sections sit straight on the page, separated by space and hairlines, with small grey section labels (`h2`) instead of boxed cards. Glass (`backdrop-filter`) only on floating things: the bottom bar, sheets, toasts and the notes format bar. No colour wash, no gradients, no hero, no mottos.
- One typeface, Inter (bundled in `fonts/inter.woff2`), with tabular numbers for times and counts. One accent, dusty blue (`#3D5A8A`, `#8FA9D6` in Night). Colour otherwise comes from the data: each course keeps its Google Calendar colour (`js/colors.js`: DHRM blueberry, Neuro grape, PerM tomato, EE&EB banana, DTS basil), deadlines red, to-dos amber. Amber, red and green are for state only.
- Thin line icons from `js/icons.js` (inline SVG, 1.6 stroke, follow the text colour) for navigation and actions; labels stay as plain words beside or under them. No emoji, no serif type, no all-caps tracked labels.
- Interactions: tapping a task or a typed event opens a bottom sheet (`app.sheets`, drawn by `renderSheet()` in `core.js` into `#sheet`), not an inline form. Rows marked `li.sw` swipe right to finish and left to reveal Snooze and Delete; anything with `data-menu="kind:id"` opens a long-press menu from `app.menus` (`js/gestures.js`). Every tap has a press state (scale .97). Deletes offer Undo through `toast()`.
- Contrast comes first; `--ink` and `--muted` are tuned for that. Light and dark are both designed and chosen in Settings (Light, Dark, Match phone). All colours are tokens at the top of `css/v3.css`; add any new colour to all three blocks (light, dark via media query, and `[data-theme="dark"]`). Widget colours live in `android-native/res/values*/dd_colors.xml` and follow Paper and Night; panes are nearly opaque so they stay readable on any wallpaper.
- Lists that can be ticked (Home to-do, Tasks, needs-attention, habits, calendar days, the Tasks and Habits widgets) keep ticked rows at the bottom, struck through, and rows glide to their new place (`data-flip`, see `render()` in `core.js`). Unticking lifts them back. Tasks ticked today stay visible; older ones move to Earlier.
- Motion is gentle (entrance rise, tick pop, list glide) and switched off by `prefers-reduced-motion`.
- Home is today as one timeline (`js/views/home.js`): the date, banners only when they matter (exams within three weeks, the weekly review on Sunday and Monday), quick add, then the day on a time rail (classes, typed events, deadlines, timed tasks, the now line, free gaps of 45 minutes or more with a Plan button that places an untimed task there), then Anytime tasks, inbox items, and habits as a row of dots. Sections with nothing to show are hidden.
- Keep `main` a single-column grid with `minmax(0, 1fr)`; without it wide content stretches past the screen.
